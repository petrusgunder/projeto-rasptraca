Controle de acesso biométrico para salas acadêmicas

Um protótipo de tranca automática que troca a chave física pela digital: backend em Flask, banco de dados em SQLite e, em breve, um leitor biométrico conectado a um microcontrolador embarcado.

01

Introdução e justificativa

Campus, prédios e laboratórios modernizam seus equipamentos rápido — mas a infraestrutura física, muitas vezes, fica para trás. No Campus Garopaba, esse descompasso aparece de forma bem concreta: não existe um sistema automatizado para controlar o acesso a salas e laboratórios.

O modelo atual depende de chaves físicas, que trazem problemas conhecidos: risco de perda, nenhuma rastreabilidade de quem entrou onde e quando, e uma logística lenta para liberar ambientes.

Este projeto propõe uma alternativa: uma tranca automática com leitura biométrica e um backend centralizado, priorizando segurança, praticidade e automação na gestão dos espaços do campus.

A consolidação da sociedade em rede tornou a informação e o controle tecnológico pilares da infraestrutura contemporânea — o que expõe o quanto os ambientes físicos ainda precisam alcançar essa mesma automação. — baseado em CASTELLS, M. A sociedade em rede. 9. ed. São Paulo: Paz e Terra, 2006.
02

Objetivos

Objetivo geral Desenvolver e validar um protótipo de sistema de controle de acesso biométrico, integrado a uma API Web, para automatizar o trancamento e a liberação das salas do Campus Garopaba.
BackendConstruir um servidor em Python com Flask para validar credenciais e registrar acessos.
DadosModelar um banco SQLite para armazenar usuários, permissões e logs.
SimulaçãoSimular a resposta da autenticação com sinalizadores visuais (LEDs) antes de integrar o atuador físico.
HardwareIntegrar futuramente o módulo leitor biométrico ao microcontrolador para leitura e envio das digitais.

Metodologia e tecnologias

Prototipagem rápida e incremental, com ferramentas escolhidas por leveza, eficiência e facilidade de integração entre software e hardware.

TecnologiaFunção no projetoPor que essa escolha
VS CodeAmbiente de desenvolvimento (IDE)Leve, modular, com bom suporte a extensões para Python e microcontroladores.
PythonLinguagem principal do backendSintaxe limpa, prototipagem rápida e um ecossistema amplo de bibliotecas de rede e dados.
FlaskAPI / micro-framework webEstrutura minimalista para criar rotas RESTful sem o peso de frameworks maiores.
SQLiteBanco de dados relacionalBanco em arquivo único, sem servidor dedicado — ideal para protótipos embarcados.
Raspberry PiPonte entre software e mundo físicoCompacto, leve e portátil, com potência suficiente para o protótipo.

Estágio atual do projeto

O projeto está na fase de validação da lógica de software e simulação dos atuadores. A API em Flask já consulta a existência da digital no banco SQLite.

1
Leitura simulada

Uma digital (simulada) é enviada para consulta no sistema.

2
Consulta na API Flask

O backend verifica a existência e a permissão da digital no banco SQLite.

3
Resposta por LED

Verde autoriza (simulando o acionamento do relé/trava); vermelho nega o acesso.

4
Próximo passo

Adquirir o leitor biométrico físico para concluir a integração entre hardware e software.

LED verde — digital encontrada, acesso autorizado
LED vermelho — digital não encontrada ou sem permissão

Pontos a definir com a equipe

Decisões ainda em aberto para a próxima etapa do relatório e da implementação final.

01 Qual o modelo específico do leitor biométrico a adquirir (ex.: módulo óptico DY50, R307 ou capacitivo)?
02 Qual microcontrolador fará a ponte entre o leitor e a API em Flask (ex.: ESP32 ou Arduino com módulo Ethernet/Wi-Fi)?
03 Qual será o mecanismo físico de travamento das portas (ex.: fecho elétrico, solenoide 12V ou fechadura eletroímã)?
04 Como será feita a gestão de permissões — professores e alunos terão horários específicos de liberação por sala?
